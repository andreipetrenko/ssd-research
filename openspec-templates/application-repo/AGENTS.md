# Инструкции AI-агенту разработчика

Агента запускает разработчик в своей IDE/CLI. Integration Service агентом не управляет.

## Порядок работы

1. `sdd start-dev <Change ID> <JIRA-KEY>` — создаёт ветку `feature/<Change ID>-<JIRA-KEY>-implementation`
   и файл `.sdd/context.md` с задачей, ссылкой на функциональную спецификацию и критериями готовности.
2. Агент читает `.sdd/context.md` и функциональную спецификацию на указанном commit.
3. Агент реализует только эту задачу и пишет тесты для каждого критерия, включая негативные сценарии.
4. Разработчик проверяет diff и тесты локально.
5. `sdd open-pr --change <Change ID> --stage implementation --jira <JIRA-KEY> --project APP --repo application-repo`.
6. Merge выполняет человек после CI и code review.

## Обязательные правила

- Не придумывай API, поля и бизнес-правила, которых нет в функциональной спецификации; при пробеле — остановись
  и задай вопрос разработчику.
- Ссылайся на файлы и разделы спецификации в описании PR.
- Не меняй код вне области задачи и не трогай чужие спецификации.
- Не включай секреты и персональные данные в код, тесты, логи и промпты.
- Не создавай Jira-задачи, не выполняй merge, не меняй права доступа и настройки CI.
